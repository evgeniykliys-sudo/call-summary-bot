# Архитектура: call-summary-bot

```
Запись (voice / audio / video / файл ≤ 20 МБ)
   │  bot.py — скачать во временную папку, очередь по одной записи (CPU)
   ▼
decode_audio()  — av: любой формат → моно 16 кГц float32
   │
   ├─► faster-whisper (small, int8, CPU)   → сегменты текста с таймкодами
   └─► sherpa-onnx (pyannote 3.0 + 3D-Speaker) → кто когда говорит
   │
   ▼
сшивка: каждому сегменту текста — говорящий с наибольшим пересечением по времени,
подряд идущие фразы одного говорящего → одна реплика «[мм:сс] Спикер N: …»
   │
   ▼
summarize.py — Claude, структурированный ответ (tool use):
участники, тезисы, решения, задачи {что, кто, срок}, открытые вопросы
   │
   ▼
Telegram: выжимка (HTML) + расшифровка файлом .txt
```

## Модули
| Модуль | Что делает |
|---|---|
| `transcribe.py` | Декодирование аудио, Whisper, сшивка с разметкой говорящих |
| `diarize.py` | Разметка говорящих (sherpa-onnx), сопоставление с сегментами Whisper |
| `summarize.py` | Выжимка через Claude, форматирование в Telegram-HTML |
| `bot.py` | Telegram: приём записей, лимит 20 МБ, очередь, доступ по ALLOWED_USER_IDS |
| `cli.py` | То же без Telegram — для больших файлов |

## Решения и почему
- **Whisper локально, а не по API.** Бесплатно, без отдельного ключа, запись не уходит в сторонний
  сервис распознавания. Цена — скорость на CPU.
- **Свой декодер аудио.** faster-whisper 1.2 вызывает `av.open(metadata_errors=…)`, в av 19 этого параметра нет,
  а старый av под Python 3.12/Windows не собирается. Декодируем сами и отдаём Whisper готовый массив.
- **Разметка говорящих — sherpa-onnx, а не pyannote.audio.** pyannote требует PyTorch (~2 ГБ) и токен HuggingFace;
  sherpa-onnx — те же модели сегментации в ONNX, без торча и токена.
- **Без разметки говорящих выжимка бесполезна для задач**: первая версия нашла все задачи и сроки, но у всех
  исполнитель «не указан» — в тексте нет, кто говорит. С разметкой — 3 из 3 исполнителей верно.
- **Порог кластеризации 0.9** подобран `scripts/calibrate_diarization.py`: на 0.5-0.7 один человек делился на
  несколько «спикеров», на 0.9 — ровно 3. Тестовые голоса синтетические (два женских — один голос TTS
  с разной высотой), поэтому живые записи различаются даже легче.
- **Имена — только по явным признакам** (обращение по имени → ответ). Если имени в разговоре не было —
  «Спикер N», модель не угадывает.
- **Очередь по одной записи** (`asyncio.Lock`): распознавание занимает CPU целиком, параллельная обработка
  только замедлит обе.
- **ALLOWED_USER_IDS**: ключ Claude платный — посторонние не должны им пользоваться.

## Проверено
- Тестовая планёрка 1:30 (3 участника): все 3 решения, 3 задачи со сроками и исполнителями, открытый вопрос —
  совпали со сценарием. Обработка ~65-70 с на CPU.
- Живой тест в Telegram: `/start`, файл mp3, голосовое — без ошибок.
